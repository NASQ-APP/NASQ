# الفرونت-إند — دولابي الذكي

React 19 · TypeScript · Vite · Tailwind v4 · Zustand · TanStack Query

```bash
npm run dev        # من جذر المشروع: npm run dev
npm run typecheck
npm run lint
```

انسخي `.env.example` باسم `.env.local` قبل ربط الخادم.

## الحالة

- **Zustand** — حالة الواجهة والبيانات المحلية (`features/*/store.ts`)
- **TanStack Query** — حالة الخادم عند ربطه (`app/providers/QueryProvider.tsx`)

**لا تُخلط الاثنتان.** خلطهما أكثر خطأ متكرر في مشاريع Supabase.

طبقة الحفظ كلها خلف [`infrastructure/storage`](src/infrastructure/storage) —
عند وصول الخادم، هذا الملف وحده هو اللي يتغيّر.

## صور القطع

ثلاث مصادر بترتيب أولوية واحد داخل
[`ItemImage`](src/shared/components/media/ItemImage.tsx):

| # | المصدر | المكان |
|---|---|---|
| ١ | صورة رفعتها المستخدمة | IndexedDB عبر `features/wardrobe/photos.ts` |
| ٢ | صورة مرفقة بالقطعة | `item.imageUrl` — يعبّيه الخادم لاحقًا عند رفع الصور له |
| ٣ | سطح فاضي هادئ | بلا رسم ولا أيقونة — اسم القطعة تحتها يكفي |

**التطبيق يبدأ بلا قطع.** الخزائن الخمس تبقى لأنها تنظيم مو ملابس. ومن جرّب
نسخة سابقة كانت تحمل قطعًا تجريبية، تنحذف عنده مرة وحدة عند أول تشغيل
(هجرة الإصدار ٢ في [wardrobe/store.ts](src/features/wardrobe/store.ts)):
المعيار أن ما تضيفه المستخدمة يحمل معرّفًا ببادئة `item_`، وأي معرّف غيره جاء
من بيانات العرض — فما تُمسّ قطعة أضافتها بنفسها.

**ليش IndexedDB مو localStorage:** الصورة عشرات الكيلوبايتات، ومخزن Zustand
يُكتب كاملاً مع كل تعديل — فحشو الصور فيه يبطّئ كل عملية ويصطدم بسقف التخزين.

الرفع يمر من [`prepareForStorage`](src/infrastructure/images/prepare.ts): قص
مربّع من المنتصف، تصغير إلى ٧٢٠ بكسل، وترميز WebP (وJPEG لو المتصفح ما يدعمه). إزالة الخلفية الحقيقية شغل
الخادم في المرحلة ٢ — هنا تجهيز عرض فقط.

عند وصول الخادم: `photoStore.ts` وحده هو اللي يتغيّر لرفع إلى Supabase Storage،
ولا يتغيّر أي مكوّن واجهة.

## إزالة خلفية الصور

خدمة مركزية واحدة، ومكوّن رفع واحد يستدعيها. المسار:

```
اختيار صورة → تحقق (نوع/حجم) → إزالة الخلفية في الخادم
  → معاينة قبل/بعد → موافقة المستخدمة → حفظ
```

**ما يُحفظ شيء قبل الموافقة.** المكوّن ينادي `onConfirm` والحفظ مسؤولية
المنادي، فكل شاشة تحفظ بطريقتها.

| الطبقة | الملف | مسؤوليتها |
|---|---|---|
| المجال | [uploadMachine.ts](src/domain/images/uploadMachine.ts) | آلة حالة نقية: اختيار، معالجة، فشل، إعادة محاولة، اختيار نسخة |
| المجال | [validation.ts](src/domain/images/validation.ts) | نوع الملف وحجمه |
| البنية | [backgroundRemoval.ts](src/infrastructure/images/backgroundRemoval.ts) | `removeImageBackground(file, signal)` — النداء الوحيد للخادم |
| البنية | [prepare.ts](src/infrastructure/images/prepare.ts) | تصغير قبل الإرسال، قص مربّع قبل الحفظ، حفظ الشفافية |
| الهوك | [useBackgroundRemoval.ts](src/shared/hooks/useBackgroundRemoval.ts) | تشغيل الطلب، إلغاء السابق، تنظيف الروابط |
| الواجهة | [ImageUploader.tsx](src/shared/components/media/ImageUploader.tsx) | السحب والإفلات، المعاينة، الأزرار |

### الاستخدام

```tsx
// صور القطع — إزالة الخلفية مفعّلة افتراضيًا
<ImageUploader onConfirm={save} />

// الصورة الشخصية — بدون معالجة
<ImageUploader backgroundRemoval={false} onConfirm={save} />
```

### مواضع الرفع

| الشاشة | إزالة الخلفية | ليش |
|---|---|---|
| إضافة قطعة | ✓ | قطعة ملابس |
| تغيير صورة قطعة | ✓ | قطعة ملابس |
| الصورة الشخصية | ✗ | صورة شخص، وقصّها يشوّه النتيجة |

### مزوّدان خلف نفس الواجهة

يُختاران بـ`VITE_BACKGROUND_REMOVAL` — وهو **اختيار وضع، مو سرًّا**:

| المزوّد | وين يشتغل | يحتاج مفتاح؟ | متى يناسب |
|---|---|---|---|
| `local` (افتراضي) | المتصفح | لا | خلفية شبه موحّدة — الحالة الشائعة |
| `backend` | دالة الحافة | نعم | خلفية مزدحمة تحتاج نموذجًا |

**المحلي** في [localBackgroundRemoval.ts](src/infrastructure/images/localBackgroundRemoval.ts)
والخوارزمية النقية في [backgroundMask.ts](src/domain/images/backgroundMask.ts).
ثلاث أفكار تصنع جودته:

**١ — انتشار بخطوة محلية.** البكسل ينضم للخلفية لو كان قريبًا من **جاره**
المضموم، مو من مرجع عام واحد. الإضاءة المتدرّجة تتغيّر تدريجيًا فكل خطوة
صغيرة وتنشال الخلفية كاملة، بينما حدّ القطعة قفزة كبيرة توقف الانتشار. ومعه
سياج عام واسع يمنع الهروب داخل القطعة.

**٢ — مرحلة ظل محدودة العمق.** الظل والقطعة الغامقة ما ينفصلان بفحص بكسل
واحد: كلاهما أغمق من الخلفية بنفس درجة اللون. الفصل **مكاني**: هالة الظل شريط
رفيع ملاصق للخلفية، فنسمح لها بالانتشار ٣٫٥٪ من أصغر ضلع وبعدها تتوقف. ومعها
حدّ أدنى للعتمة (٢٠ درجة) يمنع ابتلاع قطعة فاتحة لونها قريب من الخلفية.

**٣ — المسافة في Lab وحافة ملطَّفة.** والناتج على **خلفية بيضاء** بترميز WebP:
نصف حجم JPEG بنفس الجودة.

يشتغل بلا إنترنت وبلا مفتاح وبلا تكلفة، وحدوده صريحة: الخلفية المزدحمة تحتاج
نموذجًا حقيقيًا — وقتها تُفعَّل `backend`.

### أمان

مفتاح المزوّد الخارجي يعيش في `BACKGROUND_REMOVAL_API_KEY` داخل بيئة دالة
الحافة فقط. **ما فيه أي متغيّر `VITE_` يحمل مفتاحًا** — الفرونت-إند يعرف الوضع
والمسار فقط.

## استوديو التنسيق

ثلاثة أعمدة على شبكة CSS: **الخزانة · الموديل · الإطلالة**. الجانبان يُطويان
مستقلين، وعمود الموديل `1fr` فيبتلع المساحة المتحرّرة — «الموديل هو البطل»
قاعدة مكتوبة في مكان واحد بدل ما تتناثر في الأنماط.

| الطبقة | الملف | مسؤوليتها |
|---|---|---|
| المجال | [layout.ts](src/domain/studio/layout.ts) | قالب الأعمدة · وضع التركيز · **خطة التخطيط لكل جهاز** |
| المجال | [outfit.ts](src/domain/studio/outfit.ts) | خانات الإطلالة وكشف التعارض (قميصان ما يتكدّسان) |
| المجال | [search.ts](src/domain/wardrobe/search.ts) | بحث عربي متسامح: أ/إ/آ→ا · ة→ه · ى→ي · بلا تشكيل |
| الحالة | [store.ts](src/features/studio/store.ts) | الاختيار + تفضيلات مساحة العمل، محفوظة بين الزيارات |

**شريط الاقتراحات مساحته بيد المستخدمة:** تسحب حافته العليا لتوسّعه أو
تصغّره (٩٢–٣٤٠ بكسل)، أو تطويه فيرجع المكان كله للموديل. وفوق ١٥٦ بكسل يتحوّل
من صف أفقي إلى شبكة بطاقات تشرح **ليش** اقترحنا كل إطلالة — التوسيع يعطي
معلومة أكثر، مو نفس الصف مطّاطًا. الارتفاع محفوظ مع بقية تفضيلات مساحة العمل.

المقبض [`ResizeHandle`](src/shared/components/layout/ResizeHandle.tsx) عام
وقابل لإعادة الاستخدام: سحب بالمؤشر أو باللمس، **ومعه لوحة المفاتيح**
(الأسهم · `Home` · `End` · `Enter` للطيّ)، ويُعلن نفسه `separator` بقيمه
وحدّيه لقارئ الشاشة.

**التفاعل الأساسي سحب وإفلات**، ومعه **نقر** لأن السحب ما يشتغل باللمس ولا
بلوحة المفاتيح. المعاينة القديمة **تُعلَّم** لما يتغيّر الاختيار بدل ما تُعرض
كأنها حالية.

## الطقس

سطر واحد تحت تاريخ اليوم في الرئيسية: الدرجة والحالة والصغرى والعظمى والمدينة،
ومعها **ما يعنيه ذلك للّبس** — لأن «٣٧°» رقم، و«حار — قطن وكتان» قرار.

| الطبقة | الملف | مسؤوليتها |
|---|---|---|
| المجال | [conditions.ts](src/domain/weather/conditions.ts) | يطوي ٢٨ كود WMO إلى ثمانية أحوال بتسمياتها |
| المجال | [dressing.ts](src/domain/weather/dressing.ts) | `dressingBrief` و`weatherSentence` — الجو مترجَمًا للبس |
| المجال | [cities.ts](src/domain/weather/cities.ts) | مدن جاهزة بإحداثياتها |
| البنية | [openMeteo.ts](src/infrastructure/weather/openMeteo.ts) | المزوّد الوحيد الذي يلمس الشبكة |
| الحالة | [useWeather.ts](src/features/weather/useWeather.ts) | TanStack Query، كاش نصف ساعة |
| الواجهة | [WeatherLine.tsx](src/features/weather/components/WeatherLine.tsx) | السطر ومنتقي المدينة |

```
VITE_WEATHER_PROVIDER=open-meteo   # الافتراضي
VITE_WEATHER_PROVIDER=off          # إطفاء الميزة بلا حذف شيفرة
```

**بلا مفتاح ولا خادم:** Open-Meteo مفتوحة بلا تسجيل، والمُرسَل إحداثيات مدينة
مختارة من قائمة — ما فيه سرّ ينزل المتصفح ولا موقع فعلي للمستخدمة ولا أي بيانات
شخصية. لو استُبدل بمزوّد يطلب مفتاحًا: يُكتب مزوّد `backend` ويعيش المفتاح في
بيئة دالة الحافة، بلا لمس أي مكوّن.

**هذي أول استعمال فعلي لـTanStack Query** — الجو حالة خادم خالصة، فما تدخل
Zustand. المدينة المختارة وحدها تفضيل واجهة، فمكانها Zustand (§19).

**الوصلة مع المنسّق:** `weatherSentence(now, city)` يبني سطرًا واحدًا جاهزًا
للحقن في سؤال المنسّق («الجو في الرياض: صحو، ٣٨°…، حار — قطن وكتان»). لما
يُربط الذكاء بالطقس، ما يحتاج أحد يعيد صياغة الجو — القاعدة مكتوبة مرة وحدة
ويقرأها العرض والنموذج معًا.

## خزانة السفر

الرحلة نصفها تخطيط ونصفها حزم، فالواجهة تفتح على **وش ناقص** مو على الاسم
والتاريخ: نسبة الأيام المخطّطة، ونسبة ما حُزم، ونقطة لكل يوم في البطاقة.

| الطبقة | الملف | مسؤوليتها |
|---|---|---|
| المجال | [plan.ts](src/domain/travel/plan.ts) | `tripProgress` · `packingGroups` · `nextEmptyDay` — حساب نقي بلا DOM |
| المجال | [types.ts](src/domain/travel/types.ts) | `packingList`: قائمة الشنطة **مشتقّة** من قطع الأيام (T-04) |
| الواجهة | [TripCard.tsx](src/features/travel/components/TripCard.tsx) | حالة الرحلة في بطاقة: تقدّم · نقاط أيام · لمحة قطع |
| الواجهة | [DayCard.tsx](src/features/travel/components/DayCard.tsx) | اليوم وحدة تخطيط: تسميته تُعدَّل، وإطلالته تُعرض وتُفرَّغ |
| الواجهة | [PackingList.tsx](src/features/travel/components/PackingList.tsx) | الشنطة مقسّمة بمواضع القطع، بصور وعدّاد لكل مجموعة |

**ليش المجموعات مشتقّة:** الشنطة تُحزم بالمجموعات — الأحذية مع الأحذية — لا
بترتيب ما أُضيف للأيام. والترتيب من `SLOT_FILTERS` نفسه، فيطابق فلاتر الخزانة.

**المحزوم يُحسب من القائمة المشتقّة:** قطعة عُلّمت محزومة ثم أُخرجت من كل
الأيام ما تُعدّ — وإلا طلع العدّاد ٥/٤.

**حذف الرحلة يمرّ بتأكيد** يقول ما الذي ينحذف وما الذي لا يتأثر — كان يحذف
بنقرة واحدة بلا رجعة.

## التكيّف مع الأجهزة

نقطة توقّف واحدة معرّفة في [device.ts](src/domain/shared/device.ts)، تقرأها
الشيفرة وتقابلها كلاسات Tailwind — فما يصير عنصر مخفي بالكلاس ومحسوب بالجافاسكربت.

| الجهاز | العرض | الاستوديو |
|---|---|---|
| جوال | < ٧٦٨ | عمود واحد · اللوحتان ورقتان سفليتان · شريط تنقّل سفلي |
| لوحي | ٧٦٨–١٠٢٣ | عمودان · الخزانة مرسّاة (٢٨٠) · الإطلالة ورقة |
| سطح مكتب | ≥ ١٠٢٤ | ثلاثة أعمدة · الجانبان مرسّيان ويُطويان لشريط ٥٦ |

الأدوات المشتركة:

| الأداة | ملفها | تسوي إيش |
|---|---|---|
| `useMediaQuery` | [useMediaQuery.ts](src/shared/hooks/useMediaQuery.ts) | استعلام وسائط عبر `useSyncExternalStore` — يُقرأ وقت الرسم فما يومض |
| `useDeviceClass` | [useDeviceClass.ts](src/shared/hooks/useDeviceClass.ts) | جوال · لوحي · سطح مكتب |
| `studioLayout` | [layout.ts](src/domain/studio/layout.ts) | خطة نقية: قالب الأعمدة + مكان كل لوحة |
| `AdaptivePanel` | [AdaptivePanel.tsx](src/shared/components/layout/AdaptivePanel.tsx) | نفس المحتوى: عمود مرسّى أو ورقة سفلية |
| `Drawer` | [Drawer.tsx](src/shared/components/ui/Drawer.tsx) | يدخل من الجانب على سطح المكتب ومن الأسفل تحته (`adaptive`) |
| `Modal` | [Modal.tsx](src/shared/components/ui/Modal.tsx) | ورقة سفلية بعرض كامل تحت `sm`، نافذة مركزية فوقها |

**ليش ورقة سفلية على الجوال:** الإبهام يوصل أسفل الشاشة ولا يوصل حافتها
البعيدة. ولأن المحتوى يُعلن **مرّة واحدة**، ما فيه نسختان تتفرّع سلوكياتهما.


## الحساب

صفحتان خارج قشرة التطبيق (بلا شريط جانبي): `/signup` و`/login`.

**الحساب اختياري تمامًا** — ما فيه أي حارس يوقف المستخدمة عن دخول دولابها،
وكل صفحة فيها «أكمل بدون حساب».

| الطبقة | الملف | مسؤوليتها |
|---|---|---|
| المجال | [validation.ts](src/domain/auth/validation.ts) | مخططات Zod — النموذج والاختبار يقرآن نفس القاعدة |
| المجال | [types.ts](src/domain/auth/types.ts) | `AuthProvider` ورموز الأخطاء برسائلها العربية |
| البنية | [localProvider.ts](src/infrastructure/auth/localProvider.ts) | ملف شخصي على الجهاز |
| الحالة | [store.ts](src/features/auth/store.ts) | الجلسة |
| الواجهة | [AuthLayout.tsx](src/features/auth/components/AuthLayout.tsx) | لوحة العلامة + النموذج |

**كلمة المرور ما تُخزَّن.** تخزينها في المتصفح يعطي أمانًا كاذبًا — أي أحد يفتح
الجهاز يوصل الخزانة أصلاً. تُستخدم للتحقق من الشكل لين يجي الخادم.

**`syncsAcrossDevices: false`** تخلي الواجهة تصرّح إن الحساب يميّز الدولاب على
هذا الجهاز فقط، بدل ما توهم بمزامنة غير موجودة (المبدأ ٤). إضافة المزامنة
(X-04) = مزوّد جديد في `infrastructure/auth` + متغيّر بيئة، بلا لمس أي صفحة.
