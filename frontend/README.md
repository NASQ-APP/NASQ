# الفرونت-إند — دولابي الذكي

React 19 · TypeScript · Vite · Tailwind v4 · Zustand · TanStack Query

```bash
npm run dev        # من جذر المشروع: npm run dev
npm run typecheck
npm run lint
```

انسخي `.env.example` باسم `.env.local` قبل ربط الخادم.

---

## الهيكلة

طبقات واضحة، والاعتماد يمشي في اتجاه واحد فقط:

```
presentation → application → domain ← infrastructure
```

```
src/
├── theme/            ★ نظام التصميم: tokens.ts + theme.css
├── domain/             القواعد والأنواع النقية — بدون React وبدون إدخال/إخراج
│   ├── shared/         Gender · BodySlot
│   ├── wardrobe/       الأنواع · الفئات · الألوان · الأشكال · الفلترة
│   ├── model/          الموديل والصورة الشخصية
│   └── outfit/         عقود التجربة · الزاوية · الإكمال المحايد · البرومبت · الأخطاء
├── infrastructure/     كل ما يلمس العالم الخارجي
│   ├── http/           عميل الشبكة + مسارات الباك-إند
│   ├── tryon/          سجل المزوّدين: محلي · خادم · فحص الصورة
│   ├── rendering/      رسم الموديل بالـSVG مع طبقات الملابس عليه
│   └── storage/        مفاتيح التخزين المحلي · هجرة الاسم القديم · صور IndexedDB
├── features/           كل ميزة مغلّفة: مكوّناتها ومخزنها وهوكاتها
│   ├── wardrobe/ · studio/ · looks/ · stylist/
│   └── travel/ · try-pieces/ · ai-model/ · profile/
├── shared/           ★ ما يُعاد استخدامه في كل مكان
│   ├── components/ui/  مكتبة المكوّنات — ملف لكل مكوّن
│   ├── components/layout/  الحاوية الموحّدة للصفحات
│   ├── hooks/ · lib/ · config/
├── app/                تركيب التطبيق: المزوّدات · الراوتر · القشرة
├── pages/              شاشة لكل مسار
└── data/               خزانة البداية التجريبية
```

### قواعد الطبقات

| الطبقة | تستورد من | ممنوع عليها |
|---|---|---|
| `domain` | `domain` فقط | React · شبكة · تخزين · مكوّنات |
| `infrastructure` | `domain` · `shared` · `theme` | `features` · `pages` |
| `features` | كل ما فوق | `pages` |
| `pages` · `app` | كل ما فوق | — |

سبب المنع: منطق العمل (زاوية الكاميرا، الإكمال المحايد، الفلترة، بناء البرومبت)
لازم يبقى قابلاً للنقل للخادم بدون سحب أي شي من الواجهة معه.

## طبقة الذكاء

كل التطبيق يتكلم مع واجهة واحدة: `VirtualTryOnProvider` في
[`domain/outfit/types.ts`](src/domain/outfit/types.ts).

```
VITE_TRYON_PROVIDER=local     # تركيب محلي في المتصفح (الافتراضي)
VITE_TRYON_PROVIDER=backend   # توليد حقيقي خلف Edge Function
```

تبديل المزوّد **متغيّر بيئة واحد**، ولا مكوّن واجهة يتغيّر.
**مفاتيح أي مزوّد ما تنزل هنا أبدًا** — تعيش في الباك-إند.

| الملف | يسوي إيش |
|---|---|
| `domain/outfit/framing.ts` | اختيار زاوية الكاميرا من القطع المختارة |
| `domain/outfit/completion.ts` | الإكمال المحايد — قطعة وحدة ما تُعرض على جسم نصف عارٍ |
| `domain/outfit/prompt.ts` | بناء البرومبت ديناميكيًا |
| `domain/outfit/errors.ts` | سبعة رموز خطأ بلغة بشر |
| `infrastructure/tryon/localProvider.ts` | تركيب محلي، وكل نتيجة معلّمة `simulated` |
| `infrastructure/tryon/backendProvider.ts` | توليد غير متزامن: `jobId` فورًا ثم متابعة |
| `features/stylist/suggest.ts` | الستايليست: من خزانتك فقط، ويقول وش ناقص |

## الحالة

- **Zustand** — حالة الواجهة والبيانات المحلية (`features/*/store.ts`)
- **TanStack Query** — حالة الخادم عند ربطه (`app/providers/QueryProvider.tsx`)

**لا تُخلط الاثنتان.** خلطهما أكثر خطأ متكرر في مشاريع Supabase.

طبقة الحفظ كلها خلف [`infrastructure/storage`](src/infrastructure/storage) —
عند وصول الخادم، هذا الملف وحده هو اللي يتغيّر.

## صور القطع

ثلاث مصادر بترتيب أولوية واحد داخل
[`ItemImage`](src/shared/components/media/ItemImage.tsx):

| # | المصدر | المكان |
|---|---|---|
| ١ | صورة رفعتها المستخدمة | IndexedDB عبر `features/wardrobe/photos.ts` |
| ٢ | صورة مرفقة بالقطعة | `item.imageUrl` — يعبّيه الخادم لاحقًا عند رفع الصور له |
| ٣ | سطح فاضي هادئ | بلا رسم ولا أيقونة — اسم القطعة تحتها يكفي |

**ليش IndexedDB مو localStorage:** الصورة عشرات الكيلوبايتات، ومخزن Zustand
يُكتب كاملاً مع كل تعديل — فحشو الصور فيه يبطّئ كل عملية ويصطدم بسقف التخزين.

الرفع يمر من [`preparePhoto`](src/infrastructure/rendering/imageFile.ts): قص
مربّع من المنتصف، تصغير إلى ٧٢٠ بكسل، وضغط JPEG. إزالة الخلفية الحقيقية شغل
الخادم في المرحلة ٢ — هنا تجهيز عرض فقط.

عند وصول الخادم: `photoStore.ts` وحده هو اللي يتغيّر لرفع إلى Supabase Storage،
ولا يتغيّر أي مكوّن واجهة.

## إزالة خلفية الصور

خدمة مركزية واحدة، ومكوّن رفع واحد يستدعيها. المسار:

```
اختيار صورة → تحقق (نوع/حجم) → إزالة الخلفية في الخادم
  → معاينة قبل/بعد → موافقة المستخدمة → حفظ
```

**ما يُحفظ شيء قبل الموافقة.** المكوّن ينادي `onConfirm` والحفظ مسؤولية
المنادي، فكل شاشة تحفظ بطريقتها.

| الطبقة | الملف | مسؤوليتها |
|---|---|---|
| المجال | [uploadMachine.ts](src/domain/images/uploadMachine.ts) | آلة حالة نقية: اختيار، معالجة، فشل، إعادة محاولة، اختيار نسخة |
| المجال | [validation.ts](src/domain/images/validation.ts) | نوع الملف وحجمه |
| البنية | [backgroundRemoval.ts](src/infrastructure/images/backgroundRemoval.ts) | `removeImageBackground(file, signal)` — النداء الوحيد للخادم |
| البنية | [prepare.ts](src/infrastructure/images/prepare.ts) | تصغير قبل الإرسال، قص مربّع قبل الحفظ، حفظ الشفافية |
| الهوك | [useBackgroundRemoval.ts](src/shared/hooks/useBackgroundRemoval.ts) | تشغيل الطلب، إلغاء السابق، تنظيف الروابط |
| الواجهة | [ImageUploader.tsx](src/shared/components/media/ImageUploader.tsx) | السحب والإفلات، المعاينة، الأزرار |

### الاستخدام

```tsx
// صور القطع — إزالة الخلفية مفعّلة افتراضيًا
<ImageUploader onConfirm={save} />

// الصورة الشخصية — بدون معالجة
<ImageUploader backgroundRemoval={false} onConfirm={save} />
```

### مواضع الرفع

| الشاشة | إزالة الخلفية | ليش |
|---|---|---|
| إضافة قطعة | ✓ | قطعة ملابس |
| تغيير صورة قطعة | ✓ | قطعة ملابس |
| الصورة الشخصية | ✗ | صورة شخص، وقصّها يشوّه النتيجة |

### مزوّدان خلف نفس الواجهة

يُختاران بـ`VITE_BACKGROUND_REMOVAL` — وهو **اختيار وضع، مو سرًّا**:

| المزوّد | وين يشتغل | يحتاج مفتاح؟ | متى يناسب |
|---|---|---|---|
| `local` (افتراضي) | المتصفح | لا | خلفية شبه موحّدة — الحالة الشائعة |
| `backend` | دالة الحافة | نعم | خلفية مزدحمة تحتاج نموذجًا |

**المحلي** في [localBackgroundRemoval.ts](src/infrastructure/images/localBackgroundRemoval.ts)
والخوارزمية النقية في [backgroundMask.ts](src/domain/images/backgroundMask.ts).
ثلاث أفكار تصنع جودته:

**١ — انتشار بخطوة محلية.** البكسل ينضم للخلفية لو كان قريبًا من **جاره**
المضموم، مو من مرجع عام واحد. الإضاءة المتدرّجة تتغيّر تدريجيًا فكل خطوة
صغيرة وتنشال الخلفية كاملة، بينما حدّ القطعة قفزة كبيرة توقف الانتشار. ومعه
سياج عام واسع يمنع الهروب داخل القطعة.

**٢ — مرحلة ظل محدودة العمق.** الظل والقطعة الغامقة ما ينفصلان بفحص بكسل
واحد: كلاهما أغمق من الخلفية بنفس درجة اللون. الفصل **مكاني**: هالة الظل شريط
رفيع ملاصق للخلفية، فنسمح لها بالانتشار ٣٫٥٪ من أصغر ضلع وبعدها تتوقف. ومعها
حدّ أدنى للعتمة (٢٠ درجة) يمنع ابتلاع قطعة فاتحة لونها قريب من الخلفية.

**٣ — المسافة في Lab وحافة ملطَّفة.** والناتج على **خلفية بيضاء** بترميز WebP:
نصف حجم JPEG بنفس الجودة.

يشتغل بلا إنترنت وبلا مفتاح وبلا تكلفة، وحدوده صريحة: الخلفية المزدحمة تحتاج
نموذجًا حقيقيًا — وقتها تُفعَّل `backend`.

### أمان

مفتاح المزوّد الخارجي يعيش في `BACKGROUND_REMOVAL_API_KEY` داخل بيئة دالة
الحافة فقط. **ما فيه أي متغيّر `VITE_` يحمل مفتاحًا** — الفرونت-إند يعرف الوضع
والمسار فقط.

### التعبئة التلقائية

مصدران يمشيان معًا عند اختيار الصورة:

| الطبقة | الملف | مسؤوليتها |
|---|---|---|
| المجال | [analysis.ts](src/domain/images/analysis.ts) | يحوّل مخرج المزوّد لقيم يعرفها التطبيق ويسقط المخترَع |
| المجال | [colorMatch.ts](src/domain/wardrobe/colorMatch.ts) | أقرب لون في اللوحة بمسافة Lab |
| البنية | [dominantColor.ts](src/infrastructure/images/dominantColor.ts) | يقرأ لون القطعة من البكسلات محليًا |
| البنية | [analyze.ts](src/infrastructure/images/analyze.ts) | `analyzeGarment(image, signal)` — النداء الوحيد للخادم |
| الهوك | [useGarmentAnalysis.ts](src/shared/hooks/useGarmentAnalysis.ts) | يجمع القراءتين ويبلّغ بالنتيجة |

**ليش المسافة في Lab مو RGB:** الأسود `#1B1B1B` والكحلي `#2C3340` قريبان رقميًا
وبعيدان للعين. المسافة في RGB تخلط بينهما.

**اللون المحلي يغلب مخرج المزوّد** لأنه مقروء من بكسلات الصورة نفسها.
